# 仓库贡献指南

## 项目结构与模块组织

本项目为花花账本 V2，是采用粉色主题的个人财务管理应用，以单个独立文件 `花花账本V2.html` 交付。页面结构、CSS、JavaScript、图标和插画均内嵌在文件中。JavaScript 包含财务数据校验、本地账号加密和账本界面逻辑。

当前没有独立资源目录、软件包依赖、构建配置或随项目保存的测试脚本。不要假定之前的多文件网站或开发脚本也存在于本目录。

## 构建、测试与开发命令

可直接双击 HTML 文件，也可以在 PowerShell 中运行：

```powershell
Start-Process '.\花花账本V2.html'
```

无需构建或安装依赖。如已安装 Python，可临时启动 HTTP 预览：

```powershell
python -m http.server 4175 --bind 127.0.0.1
```

访问 `http://127.0.0.1:4175/` 并选择 HTML 文件。直接打开文件与 HTTP 预览使用不同的浏览器存储环境；测试时请使用可丢弃的临时账号。

## 代码风格与命名规范

保留单文件运行方式、中文界面和粉色主题。避免引入外部脚本、字体、服务或必须运行的服务器。新增多行代码使用两个空格缩进；函数和变量采用 `camelCase`，常量使用大写字母，例如 `ACCOUNT_KEY`。不要进行与当前修改无关的整体格式调整。目前未配置代码格式化或静态检查工具。

## 测试要求

当前未配置测试框架或覆盖率门槛。手动验证注册、用户名重复、错误密码、账号隔离、退出登录以及刷新后重新登录。同时检查记录编辑与删除、预算、筛选、图表、JSON 恢复和 CSV 导出。

使用临时测试数据，确认保存失败时原有记录仍保留。检查桌面和窄屏布局。区分 HTTP 预览验证与直接打开文件的验证；浏览器或工具限制应明确说明。后续新增自动化检查时，使用 `*.test.mjs` 命名，并记录执行命令。

## 安全与数据兼容性

账号仅存在于当前浏览器，不提供服务端身份验证或跨设备同步。除非提供迁移方案，否则保留 `petal-html-accounts-v2` 存储键和现有数据格式。密码派生密钥使用 PBKDF2/SHA-256，账目使用 AES-GCM 加密；保持随机盐值、每次加密使用新的初始化向量（IV），并将加密内容绑定到对应账号。禁止存储明文密码或持久化保存解密密钥。

保留整数“分”金额计算、导入校验、存储冲突检测和安全文本显示。JSON 导出包含明文账目，必须保留相关提示。不要静默覆盖无法读取的账号数据。

## 提交与合并请求规范

本目录没有 Git 历史。引入版本控制后，提交说明应简短、以动作开头，例如“修复预算计算”。合并请求应说明行为变化、已完成的验证、数据存储兼容性及剩余限制。界面变化需附截图，并在适用时关联相关问题。
