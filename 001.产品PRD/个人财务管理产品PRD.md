# 个人财务管理产品需求文档（PRD）

版本：V1.1｜日期：2026-10-31｜状态：初稿，已明确粉嫩可爱的视觉方向

## 1. 产品定位

面向希望每天记录消费、了解资金去向的个人用户，提供快速记账、收支查询、月度预算和消费分析。核心价值是帮助用户回答：今天花了多少、这个月钱花在哪里、预算还剩多少。

本稿默认采用适配手机和电脑的响应式网页，以人民币和单用户本地使用为首版范围。这些是规划假设，正式开发前可根据实际需求调整。

## 2. 用户与使用场景

目标用户为有日常消费记录习惯、希望控制开支但不需要复杂会计功能的个人。

- 消费后：快速记录午餐、交通或购物支出。
- 晚间：补录当天消费，核对当天支出。
- 月中：查看预算使用情况，调整消费安排。
- 月末：按分类回顾支出，并导出数据备份。

## 3. 产品目标与范围

首版目标：让用户完成一笔记账的核心操作控制在四步以内；在一个页面内查看当月支出和剩余预算；保证记录可修改、可删除、可备份。

| 优先级 | 功能 | 交付范围 |
| --- | --- | --- |
| P0 | 收支记账 | 新增、编辑、删除，记录金额、分类、日期、备注 |
| P0 | 收支明细 | 按日分组，按月份、类型和分类筛选 |
| P0 | 首页概览 | 今日支出、月度收入、支出、收支差额 |
| P0 | 月度预算 | 设置总支出预算，显示剩余金额与超支提醒 |
| P0 | 基础统计 | 分类占比、每日支出趋势 |
| P0 | 数据管理 | 本地保存、JSON 备份导入导出、CSV 导出 |
| P1 | 使用效率 | 备注搜索、自定义分类、常用记账模板 |
| 后续 | 多端能力 | 用户账户、云同步、多设备冲突处理 |

首版不包含银行卡连接、自动扣款、支付、投资交易、多人账本或税务申报。首页的“收支差额”仅表示所选期间收入减支出，不表示银行余额或净资产。

## 4. 信息架构与关键流程

主要页面：首页、记一笔、明细、统计、设置。手机底部固定导航提供首页、明细、统计和设置；醒目的“记一笔”入口在主要页面均可访问。

核心流程：打开产品 → 点击记一笔 → 输入金额 → 选择分类 → 保存 → 返回原页面并更新统计。日期默认当天，类型默认支出，备注可留空；不强制选择支付账户。

补录流程：记一笔 → 修改日期 → 保存 → 对应日期和月份的明细、统计同步更新。

纠错流程：明细 → 点击记录 → 编辑并保存，或删除 → 二次确认 → 统计重新计算。

## 5. 功能需求

### 5.1 记一笔

字段包括类型、金额、分类、发生日期和备注。类型支持支出、收入。金额必须大于零，最多两位小数，单笔不超过 99,999,999.99 元；日期按本地日历日期记录，首版不允许未来日期；备注最多 200 个字符。

支出预置餐饮、交通、购物、居住、娱乐、医疗、学习和其他；收入预置工资、奖金和其他。分类必须属于当前收支类型。切换类型时清空不匹配的分类，不清空金额和备注。

保存时校验必填项，错误提示靠近对应字段；保存过程中禁用重复提交。成功后提示“已记账”，失败时保留输入，并明确告知尚未保存。

### 5.2 首页与预算

默认展示当月数据，可切换历史月份。今日支出始终指本地当天支出，并明确显示日期。首页展示所选月份的收入、支出、差额，以及最近五笔记录。

月度预算独立保存，金额必须大于零；未设置时展示“设置本月预算”。所有支出分类均计入预算，收入不抵扣支出。剩余预算＝月度预算－当月支出，负值显示为超支金额。达到 80% 时提示“预算已使用 80%”；达到或超过 100% 时提醒超支，但不阻止继续记账。进度条最多显示 100%，旁边保留实际使用比例。可调整或取消预算。

### 5.3 明细与统计

明细按发生日期倒序分组，同日按创建时间倒序排列，并显示每日收支小计。筛选条件可组合使用；无匹配结果时提供清除筛选入口。删除记录后只移除对应记录，预算设置保留。

统计默认展示当月支出分类占比、各分类金额和每日支出趋势。占比＝分类支出／当月总支出；总支出为零时展示空状态，不进行除零运算。收入统计与支出分开展示，不混用占比。图表提供文字金额，不能只依赖颜色传达信息。

### 5.4 数据管理

首版采用 IndexedDB 本地保存。刷新和重开浏览器后数据仍应保留；不同设备或不同浏览器的数据不自动互通。设置页提示清除浏览器数据可能导致记录丢失，并提供明显的备份入口。

JSON 备份包含记录、预算、分类和数据格式版本，用于完整恢复。导入前校验文件格式、版本、金额、日期及唯一标识；首版只支持整库替换，先展示导入摘要并要求确认，同时提供当前数据备份。校验或写入失败时保留原有数据，替换操作应在一个事务内完成。

CSV 使用 UTF-8 编码，包含日期、类型、分类、金额和备注，按当前明细筛选范围导出；正确转义逗号、引号、换行，并处理以公式字符开头的文本，避免表格软件执行公式。CSV 不作为首版恢复格式。

## 6. 数据结构与计算规则

| 数据对象 | 主要字段 | 规则 |
| --- | --- | --- |
| 收支记录 | id、type、amountFen、categoryId、occurredDate、note、createdAt、updatedAt | id 唯一，类型为 income 或 expense |
| 分类 | id、type、name、sortOrder | 首版提供固定预置分类 |
| 月预算 | month、amountFen、updatedAt | month 为 YYYY-MM，每月最多一条 |
| 备份 | schemaVersion、exportedAt、records、categories、budgets | 用版本号识别兼容性 |

所有金额以整数“分”保存和计算，显示时格式化为元，避免浮点误差。发生日期使用 YYYY-MM-DD，月份归属按该日期判断；创建及更新时间使用带时区信息的时间戳。所有概览、统计和预算使用同一套计算规则。首版不设置转账类型；退款可通过编辑原记录调整支出并在备注说明，独立退款流程留待后续设计。

## 7. 界面与交互要求

### 7.1 视觉定位与配色

整体采用粉嫩、温柔、可爱的风格，以浅粉背景、白色卡片和玫瑰粉强调色构成主界面。通过圆角、简洁插画和柔和阴影体现亲切感，同时突出金额和记账入口，确保账目容易阅读。

| 颜色角色 | 色值 | 使用场景 |
| --- | --- | --- |
| 页面底色 | `#FFF5F8` | 全局浅粉背景 |
| 卡片底色 | `#FFFFFF` | 收支卡片、表单、明细容器 |
| 主强调色 | `#B83D72` | 主按钮、当前导航、主要图表系列；按钮文字用白色 |
| 装饰浅粉 | `#FADCE8` | 分类图标底色、选中背景、轻量装饰 |
| 主要文字 | `#4A2938` | 金额、标题、正文 |
| 次要文字 | `#795366` | 日期、说明和辅助标签 |
| 收入标识 | `#4F627E` | 收入文字与标识，配合“收入”标签 |
| 警示色 | `#A52C48` | 超支、错误和删除操作，配合明确文字或图标 |

分类图表可补充柔和的蜜桃色、淡紫色和奶黄色，但粉色始终为主色。浅色用于背景，不能直接作为白底上的小字号文字。正文及普通按钮文字对比度至少为 4.5:1，大字号文字和必要的交互图形至少为 3:1；实际组合在设计验收时检查。

### 7.2 组件与文案风格

- 卡片圆角采用 20px，按钮和输入框圆角采用 12px，分类图标使用圆形或圆角容器；统一使用 8px 间距基准。
- 使用清晰的系统中文字体，正文建议不小于 16px，关键金额采用较大字号和等宽数字；避免花体字影响金额辨认。
- 可在欢迎页、空状态和记账成功反馈中使用小花、爱心或小动物插画。账单行、金额和操作按钮不堆叠装饰。
- 文案温柔简短，例如“今天也记一笔吧”“已记好这笔支出”；预算提醒使用“本月已超出预算 ¥128.00”等具体表述，不责备用户。
- 动效轻量且短暂，遵循系统减少动态效果的偏好，不用持续跳动或彩纸效果干扰操作。

### 7.3 交互与可访问性

金额层级突出，支出和收入同时使用文字标签及颜色区分。金额输入支持手机数字键盘；保存按钮保持容易触达，点击区域不小于 44×44 CSS 像素。

适配 360px 起的手机屏幕和桌面屏幕。表单配备可访问标签，支持键盘操作和清晰焦点。首次进入展示引导空状态，不写入虚假账目；加载、保存失败、存储不可用均提供明确反馈。离开未保存表单时提示可能丢失输入。

## 8. 隐私、安全与性能

首版财务记录不上传服务器，不嵌入采集记账内容的第三方分析脚本。备注按纯文本展示，避免脚本注入。页面内的本地存储不是加密保险箱，不宣传为加密账本。

在约定的测试设备和浏览器上，以 10,000 笔记录验证首页和筛选操作，交互反馈目标为一秒内；明细采用分页或分批渲染。推荐使用 localhost 或 HTTPS 访问，减少直接以文件方式打开时的存储兼容性差异。离线安装能力如需提供，应单独安排 Service Worker 和缓存测试。

## 9. 核心验收标准

| 场景 | 预期结果 |
| --- | --- |
| 新增 25.50 元餐饮支出 | 明细新增一笔；当月支出增加 25.50 元；对应预算同步减少 |
| 新增 5,000 元工资收入 | 当月收入增加，支出和预算使用额不变 |
| 将支出从 25.50 改为 20.00 元 | 记录更新，所有相关汇总减少 5.50 元 |
| 将记录日期改到上个月 | 原月份移除该金额，上个月增加该金额 |
| 删除并确认 | 记录移除，相关统计重新计算；取消删除则不改变数据 |
| 输入零、负数、三位小数或未来日期 | 保存被阻止并显示具体原因 |
| 刷新页面或关闭后重新打开 | 在同一浏览器和访问地址下，记录及预算保留 |
| 导入合法备份／损坏文件 | 前者确认后完整替换，后者报错且原数据不变 |
| 本地存储写入失败 | 不显示保存成功，保留输入供重试 |
| 空账本与零支出月份 | 不出现 NaN、错误占比或虚假账目 |
| 视觉风格与可读性 | 主要页面使用统一粉色主题、圆角组件和适量可爱元素；金额清晰，文字对比度达标 |
| 状态区分 | 收入、支出、超支、错误和选中状态均有文字或图标提示，不仅依赖颜色 |

## 10. 开发顺序与效果评估

第一阶段完成页面原型、数据字段及计算规则确认；第二阶段实现记账、明细与本地持久化；第三阶段加入预算、统计及导入导出；第四阶段进行功能、兼容性、隐私和可访问性验收。各阶段以交付结果为准，工期由实现方案和人员配置评估。

上线前通过人工任务测试评估首次记账成功率、记账耗时、查找一笔消费所需时间和备份恢复成功率。首版不自动上报使用行为；未来引入分析前，应明确告知、征得同意并避免采集金额或备注。
